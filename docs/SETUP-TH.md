# 🎀 Myrikaka — คู่มือติดตั้งระบบจริง

ทำตามทีละข้อ ใช้เวลาประมาณ **30–45 นาที** ไม่ต้องลงโปรแกรมอะไรในเครื่องเลย
ทุกอย่างทำผ่านเว็บ + เปิดไฟล์ด้วย Notepad ครั้งเดียว

**ไฟล์ในชุดนี้**

| ไฟล์ | ใช้ทำอะไร | จำเป็นไหม |
|---|---|---|
| `myrikaka-app.html` | ตัวแอปทั้งหมด — ไฟล์เดียวจบ | ✅ |
| `supabase/schema.sql` | สร้างตารางฐานข้อมูล (วางครั้งเดียว) | ✅ |
| `supabase/schema-v2.sql` | เปิดหน้าร้านให้ลูกค้าสั่งซื้อ + ที่เก็บผลเช็คสต็อก | ✅ |
| `supabase/schema-v3.sql` | เครดิตลูกค้า (ส่วนเกินจากการโอน) | ✅ |
| `supabase/functions/stock/index.ts` | ตัวดึงสต็อกสดจากเว็บญี่ปุ่น/จีน | ถ้าอยากใช้ |
| `tests/` | ชุดทดสอบที่ผมใช้ตรวจงาน | ไม่ต้องแตะ |

---

## ขั้นที่ 1 — สมัคร Supabase (ฟรี)

Supabase คือ "ฐานข้อมูลบนคลาวด์" ที่จะเก็บสินค้า ออเดอร์ รูปสลิป และบัญชีผู้ใช้ให้

1. เปิด <https://supabase.com> → กด **Start your project**
2. สมัครด้วยบัญชี Google หรืออีเมลก็ได้
3. กด **New project**
   - **Name**: `myrikaka`
   - **Database Password**: กด Generate แล้ว **คัดลอกเก็บไว้ในที่ปลอดภัย**
   - **Region**: เลือก **Southeast Asia (Singapore)** — ใกล้ไทยที่สุด
4. กด **Create new project** รอประมาณ 2 นาที

---

## ขั้นที่ 2 — สร้างตารางฐานข้อมูล (ทำ 3 รอบ)

1. แถบซ้าย → **SQL Editor** → **New query**
2. เปิด `schema.sql` ด้วย Notepad → Ctrl+A → Ctrl+C → วางในช่อง → กด **Run**
3. กด **New query** อีกครั้ง → เปิด `schema-v2.sql` → วาง → กด **Run**
4. กด **New query** อีกครั้ง → เปิด `schema-v3.sql` → วาง → กด **Run**

ถ้าขึ้น **Success. No rows returned** ทั้งสามรอบ = เรียบร้อย ✓

> ต้องรันตามลำดับ `schema.sql` → `schema-v2.sql` → `schema-v3.sql` เสมอ
> รันซ้ำกี่รอบก็ได้ ไม่พัง ถ้าไม่แน่ใจว่ารันไปหรือยัง รันใหม่ได้เลย

---

## ขั้นที่ 3 — ปิดการยืนยันอีเมล (ให้ทดสอบง่าย)

1. **Authentication** → **Sign In / Providers** → **Email**
2. ปิด **Confirm email** (toggle เป็นสีเทา) → **Save**

> เปิดกลับทีหลังก็ได้ ระบบรองรับทั้งสองแบบ

---

## ขั้นที่ 4 — เอาคีย์มาใส่ในไฟล์แอป

1. **Project Settings** (รูปเฟือง) → **API Keys** / **Data API**
2. คัดลอกสองค่านี้: **Project URL** (`https://xxxx.supabase.co`) และ **anon public** key (ยาวมาก ขึ้นต้น `eyJ...`)
3. คลิกขวาที่ `myrikaka-app.html` → **Open with** → **Notepad**
4. Ctrl+F พิมพ์ `PASTE_YOUR` จะเจอสองบรรทัดนี้:

```js
const SUPABASE_URL      = 'PASTE_YOUR_PROJECT_URL_HERE';
const SUPABASE_ANON_KEY = 'PASTE_YOUR_ANON_PUBLIC_KEY_HERE';
```

5. วางค่าจริงทับข้อความในเครื่องหมาย `'...'` ให้เหลือแบบนี้:

```js
const SUPABASE_URL      = 'https://abcdefghijk.supabase.co';
const SUPABASE_ANON_KEY = 'eyJhbGciOiJIUzI1NiIsInR5cCI6...';
```

⚠️ **อย่าลบเครื่องหมาย `'` และ `;`** วางทับเฉพาะข้อความตรงกลาง แล้วกด Ctrl+S

> ❓ **anon key เปิดเผยได้ไหม** — ได้ค่ะ มันถูกออกแบบมาให้อยู่ในหน้าเว็บ
> ตัวที่กันข้อมูลจริง ๆ คือกฎ RLS ในขั้นที่ 2
> แต่ **ห้ามเอา `service_role` key มาใส่เด็ดขาด** — อันนั้นข้ามกฎทุกอย่าง

---

## ขั้นที่ 5 — สร้างบัญชีเจ้าของร้าน

1. ดับเบิลคลิกเปิด `myrikaka-app.html` ด้วย Chrome
2. กด **สมัครใหม่** → ชื่อ `Ning` · อีเมลของคุณ · รหัสผ่าน (6 ตัวขึ้นไป) → **สร้างบัญชี**
3. คุณจะเข้าใช้งานได้ทันที **ในฐานะลูกค้า** (เห็นแค่หน้าร้าน ตะกร้า ออเดอร์ของฉัน) ← ถูกต้องแล้ว

**ทีนี้ตั้งตัวเองเป็นเจ้าของร้าน** — กลับไป Supabase → SQL Editor → New query
วางคำสั่งนี้ (เปลี่ยน `อีเมลของคุณ` เป็นอีเมลจริง):

```sql
update public.profiles
   set role = 'owner', active = true, name = 'Ning'
 where id = (select id from auth.users where email = 'อีเมลของคุณ');
```

กด **Run** → กลับมาที่แอป → **รีเฟรช (F5)** → แท็บหลังร้านโผล่ครบแล้วค่ะ ✓

> ใช้ SQL แค่ครั้งนี้ครั้งเดียว พนักงานคนต่อ ๆ ไปกดอนุมัติในแอปได้เลย

## ขั้นที่ 6 — เอาขึ้นเว็บ

**ลากไฟล์เดียวจบ ไม่ต้องสมัครอะไรเพิ่ม**

1. เปิด <https://app.netlify.com/drop>
2. ลาก `myrikaka-app.html` ไปวาง
3. ได้ลิงก์แบบ `https://ชื่อสุ่ม.netlify.app` → เปลี่ยนชื่อได้ที่ **Site configuration → Change site name**

**สำคัญ:** พอมีลิงก์แล้ว กลับไป Supabase → **Authentication → URL Configuration**
ใส่ลิงก์นั้นใน **Site URL** และเพิ่มใน **Redirect URLs** ด้วย
(ไม่งั้นล็อกอินด้วย Google/Facebook/X จะเด้งกลับไม่ถูกที่)

> อัปเดตแอปทีหลัง = ลากไฟล์ใหม่ไปวางทับที่เดิม **ข้อมูลในฐานข้อมูลไม่หาย**

## ขั้นที่ 7 — เพิ่มพนักงาน

1. ให้พนักงานเข้าลิงก์เว็บ แล้วสมัครด้วยอีเมลตัวเอง (หรือกด Google/Facebook/X)
2. ตอนนี้เขาใช้งานได้ในฐานะ**ลูกค้า** เท่านั้น
3. คุณเข้าระบบ → แท็บ **หลังร้าน** → ปุ่ม **👥 จัดการพนักงาน**
4. พิมพ์**อีเมลของเขา**ในช่องค้นหา → เขาจะโผล่ขึ้นมา
5. ติ๊ก **เปิดใช้** + เลือกบทบาท → **บันทึก**

| บทบาท | เห็นอะไร |
|---|---|
| เจ้าของร้าน | ทุกอย่าง · แก้ค่าธรรมเนียม · จัดการพนักงาน |
| ผู้จัดการ | ทุกงาน เห็นยอดเงินรวม แต่แก้ตั้งค่าระบบไม่ได้ |
| แอดมินการเงิน | ตรวจสลิป ยืนยันการชำระ · ไม่เห็นยอดรวมทั้งร้าน |
| แอดมินสั่งซื้อ | ใบสั่งซื้อ + ข้อมูลสินค้า · ไม่เห็นยอดเงิน |
| แอดมินคลัง | รอบขนส่ง เลขพัสดุ สถานะจัดส่ง · ไม่เห็นยอดเงิน |
| แอดมินแช็ต | ข้อมูลลูกค้าและสถานะออเดอร์ · ไม่เห็นยอดเงิน |

> **ถอนสิทธิ์คนที่ออกจากงาน**: เอาติ๊ก "เปิดใช้" ออก เขาจะกลับไปเป็นลูกค้าธรรมดาทันที
> ข้อมูลที่เขาเคยแก้ยังอยู่ครบในประวัติการทำงาน

## ขั้นที่ 8 — เปิดล็อกอินด้วยโซเชียล

ตอนนี้แอปแสดงปุ่ม **Google · Facebook · X** ไว้แล้ว แต่จะกดได้ต้องไปเปิดใน Supabase ก่อน
ถ้ายังไม่ได้เปิดอันไหน กดแล้วจะขึ้นข้อความบอกว่ายังไม่เปิดใช้งาน

**ที่อยู่ callback ที่ทุกเจ้าต้องใช้เหมือนกัน:**

```
https://<โปรเจกต์ของคุณ>.supabase.co/auth/v1/callback
```

### Google (ง่ายที่สุด แนะนำให้ทำอันนี้ก่อน)

1. <https://console.cloud.google.com> → สร้างโปรเจกต์ → **APIs & Services → Credentials**
2. **Create Credentials → OAuth client ID → Web application**
3. **Authorized redirect URIs** ใส่ที่อยู่ callback ข้างบน
4. ได้ **Client ID** กับ **Client Secret** มา
5. Supabase → **Authentication → Providers → Google** → เปิด → วางทั้งสองค่า → **Save**

### Facebook

1. <https://developers.facebook.com> → **My Apps → Create App** → เลือก **Consumer**
2. เพิ่มผลิตภัณฑ์ **Facebook Login** → **Settings** → ใส่ callback ใน **Valid OAuth Redirect URIs**
3. **App Settings → Basic** → คัดลอก **App ID** และ **App Secret**
4. Supabase → **Providers → Facebook** → เปิด → วาง → **Save**

### X (Twitter)

1. <https://developer.x.com> → **Projects & Apps** → สร้างแอป
2. **User authentication settings** → เปิด OAuth 2.0 → ใส่ callback
3. คัดลอก **Client ID** และ **Client Secret**
4. Supabase → **Providers → Twitter** → เปิด → วาง → **Save**

### LINE — ต้องตั้งค่าแบบพิเศษ

**LINE ไม่ได้อยู่ในรายชื่อมาตรฐานของ Supabase** แต่เพิ่มเองได้ผ่าน "Custom OIDC Provider"
(แผนฟรีเพิ่มได้ 3 ช่องทาง)

1. <https://developers.line.biz/console/> → สร้าง **Provider** → สร้าง **LINE Login channel**
2. ใน **LINE Login** → **Callback URL** ใส่ที่อยู่ callback ข้างบน
3. เปิด **OpenID Connect** และขอสิทธิ์ **email** (ต้องยื่นขออนุมัติในหน้า OpenID Connect)
4. คัดลอก **Channel ID** (= Client ID) และ **Channel secret** (= Client Secret)
5. Supabase → **Authentication → Providers** → เลื่อนลงล่างสุด → **Add custom provider** → เลือก **OIDC**
   - **Provider name (unique id)**: `line`  ← ต้องเป็นคำนี้เป๊ะ ๆ
   - **Issuer URL**: `https://access.line.me`
   - **Client ID / Client Secret**: จากข้อ 4
   - **Scopes**: `openid profile email`
6. เปิดไฟล์ `myrikaka-app.html` ด้วย Notepad → หาบรรทัด

```js
const LINE_PROVIDER = '';
```

แก้เป็น

```js
const LINE_PROVIDER = 'custom:line';
```

บันทึก แล้วลากไฟล์ขึ้น Netlify ใหม่ → ปุ่ม LINE จะโผล่มาค่ะ

### เปิด "Manual Linking" — สำคัญมาก อย่าลืม

ลูกค้าคนเดียวกันอาจเข้าทาง LINE บ้าง X บ้าง ถ้าไม่เปิดข้อนี้ ระบบจะนับเป็นคนละคน
เห็นออเดอร์คนละชุด และต้องยืนยันตัวตนใหม่ทุกช่องทาง

1. Supabase → **Authentication** → **Sign In / Providers**
2. เลื่อนหาหัวข้อ **Manual Linking** (หรือ **Allow manual linking**)
3. **เปิด** สวิตช์ → **Save**

พอเปิดแล้ว ลูกค้าจะเชื่อมเองได้ที่ **ออเดอร์ของฉัน → 🔗 บัญชีที่เชื่อมไว้**
กดปุ่ม "＋ เชื่อมบัญชี" ของช่องทางที่ต้องการ ครั้งเดียวจบ

> **LINE ไม่ให้อีเมลมา** จึงรวมอัตโนมัติไม่ได้ ต้องให้ลูกค้ากดเชื่อมเอง
> ส่วนช่องทางที่ให้อีเมลตรงกัน (เช่น Google กับอีเมลที่สมัครไว้) Supabase รวมให้เองอัตโนมัติ

---

> **ไม่อยากใช้ช่องทางไหน** ให้ลบชื่อออกจากบรรทัดนี้ในไฟล์แอป
> ```js
> const LOGIN_WITH = ['google', 'facebook', 'twitter'];
> ```
> เช่นอยากได้แค่ Google ก็เหลือ `['google']`

## ขั้นที่ 9 — เปิดการเช็คสต็อกสดจากเว็บต้นทาง

การดึงข้อมูลจากเว็บญี่ปุ่นทำจากหน้าเว็บตรง ๆ ไม่ได้ (เบราว์เซอร์บล็อก)
ต้องมีตัวช่วยฝั่งเซิร์ฟเวอร์ ซึ่ง Supabase มีให้ฟรีอยู่แล้ว **และติดตั้งผ่านหน้าเว็บได้เลย ไม่ต้องลงโปรแกรม**

1. Supabase → แถบซ้าย → **Edge Functions**
2. กด **Deploy a new function** → เลือก **Via Editor**
3. ตั้งชื่อว่า **`stock`** ← ต้องเป็นคำนี้เป๊ะ ๆ
4. ลบโค้ดตัวอย่างที่ขึ้นมาให้หมด แล้ววางเนื้อหาทั้งไฟล์ของ `supabase/functions/stock/index.ts`
5. กด **Deploy function** รอ 10–30 วินาที

**วิธีใช้:** เข้าแท็บ **📚 ฐานข้อมูลสินค้า** → กด ▶ หน้ารายการสินค้าเพื่อกางออก
จะเห็นปุ่ม **🔄 เช็คสต็อกสด** ใต้ช่องลิงก์ต้นทาง
หรือกด **🔄 เช็คสต็อกทั้งหน้า** ในแถบเครื่องมือด้านบนเพื่อเช็คทั้งหน้าในทีเดียว

ระบบจะอัปเดตให้อัตโนมัติ: ราคาต้นทางล่าสุด · สถานะเปิด/ปิดรับ/ของหมด · วันที่เช็ค
และถ้าราคาขยับจะเด้งบอก เช่น *"ราคาต้นทางเปลี่ยน 3900 → 4208"*

## ขั้นที่ 10 — (ทางเลือก) ทำให้เว็บจีนดึงได้ด้วย

Tmall / Taobao / Bilibili บล็อกการดึงข้อมูลอัตโนมัติ และสร้างหน้าด้วย JavaScript
ต้องผ่านบริการที่รันเบราว์เซอร์จริงให้ ซึ่ง**มีค่าใช้จ่ายรายเดือน**

1. สมัคร <https://www.scraperapi.com> หรือ <https://www.scrapingbee.com> (มีโควตาฟรีให้ลองก่อน)
2. คัดลอก **API Key**
3. Supabase → **Edge Functions** → เลือกฟังก์ชัน `stock` → **Secrets** (หรือ Settings → Edge Functions → Secrets)
4. เพิ่ม 2 ตัวนี้:
   - `SCRAPE_KEY` = API key ของคุณ
   - `SCRAPE_PROVIDER` = `scraperapi` หรือ `scrapingbee`
5. กด Save แล้วลองกดเช็คสต็อกลิงก์จีนอีกครั้ง

> ถ้าไม่ได้ตั้งค่านี้ ระบบจะไม่พัง แค่ขึ้นข้อความว่า
> *"เว็บจีนบล็อกการดึงตรง — ต้องตั้งค่า SCRAPE_KEY ก่อน"*

## ลูกค้าใช้งานยังไง

1. เข้าลิงก์เว็บ → กด **Google / Facebook / X / LINE** หรือสมัครด้วยอีเมล
2. ระบบให้อ่านนโยบายและกรอกชื่อ + เบอร์โทร
3. ถ้าเคยสั่งกับร้านมาก่อน จะมีป๊อปอัพถามว่าอยากดึงออเดอร์เก่ามารวมไหม
   → กรอกเบอร์ + **เลขคำสั่งซื้อ 4 ตัวท้าย** → ระบบผูกให้เอง (ผิดได้วันละ 3 ครั้ง)
4. เลือกสินค้า → ตะกร้า → ชำระเงิน → ดูสถานะได้ที่ **ออเดอร์ของฉัน**

**สิ่งที่ลูกค้าทำไม่ได้ (ฐานข้อมูลปฏิเสธเอง ไม่ใช่แค่ซ่อนปุ่ม)**

- เห็นออเดอร์ของคนอื่น แม้จะรู้เลขออเดอร์
- แก้ราคาสินค้า จำนวน สถานะจัดส่ง เลขพัสดุ รอบขนส่ง
- เปลี่ยนออเดอร์ตัวเองเป็นสถานะ "จัดส่งแล้ว"
- โอนออเดอร์ให้บัญชีอื่น หรือลบออเดอร์
- เห็นค่าธรรมเนียมช้อปปี้ที่คุณตั้งไว้
- ตั้งตัวเองเป็นพนักงานหรือเจ้าของร้าน
- แก้ข้อมูลสินค้าในร้าน หรือเขียนประวัติการทำงาน

**สิ่งที่ลูกค้าทำได้** — แก้ชื่อ/เบอร์/ที่อยู่ของตัวเอง · ยืนยันที่อยู่ · แนบสลิป · ขอรวมส่ง · สั่งซื้อใหม่

## รวมออเดอร์ · แยกออเดอร์ · เครดิตลูกค้า

### รวมหลายออเดอร์เป็นใบเดียว

ทำได้ 2 ทาง
- **ลูกค้าขอมา** → คุณกด **อนุมัติและรวม** ในหน้าออเดอร์หลังร้าน
- **พนักงานกดรวมเอง** → ในการ์ดออเดอร์ กด **🔗 รวมกับออเดอร์อื่น** แล้วติ๊กเลือก

รวมแล้วจะได้ใบเดียว **ใช้เลขของใบที่สั่งก่อนสุด** และแสดงเลขเดิมทุกใบไว้ใต้การ์ด
ลูกค้า**ยืนยันที่อยู่ครั้งเดียว** ค่าส่งคิดครั้งเดียว ปริ้นใบปะหน้าใบเดียว

> ระบบล้างค่าส่งเดิมเป็น 0 ให้พนักงานคิดค่าส่งรวมใหม่
> รวมได้เฉพาะออเดอร์ของลูกค้าคนเดียวกัน และยังไม่จัดส่ง

### แยกกลับ

กด **✂️ แยกกลับ** ในใบรวม → คืนสภาพเดิมเป๊ะ ทั้งเลขออเดอร์ ค่าส่ง และยอดที่เคยชำระ
เงินที่จ่ายเข้ามา*หลัง*รวม จะกลายเป็น**เครดิตของลูกค้า** ไม่หายไปไหน

### เครดิตลูกค้า

กดปุ่ม **💰 บันทึกการชำระ** ในการ์ดออเดอร์ → ใส่ยอดที่ลูกค้าโอนมาจริง
→ แบ่งลงออเดอร์ที่ค้างได้หลายใบพร้อมกัน (มีปุ่มเติมอัตโนมัติ)
→ **ส่วนที่เหลือเก็บเป็นเครดิตให้เอง**

ใช้เครดิตจ่ายออเดอร์อื่น: เลือกช่องทางเป็น **หักจากเครดิต**

> 🔒 **ไม่มีช่องให้พิมพ์ยอดเครดิตเอง** — ตั้งใจออกแบบแบบนี้เพื่อกันการเติมพลาด
> เครดิตเกิดได้ 2 ทางเท่านั้น: ① ลูกค้าโอนเกิน ② แยกใบรวมส่ง
> ถ้าบันทึกผิด เจ้าของร้านกด **ดูที่มา → ยกเลิกรายการนี้** ได้ (ระบบใส่รายการกลับรายการ ไม่ลบของเดิม)

## ใช้งานประจำวัน

- **ทุกคนเห็นข้อมูลชุดเดียวกัน** พนักงานแก้ที่เครื่องหนึ่ง อีกเครื่องเห็นทันทีโดยไม่ต้องรีเฟรช
- **มุมขวาล่าง** มีป้ายบอกสถานะ *กำลังบันทึก… / บันทึกแล้ว ✓* ถ้าแดง = เน็ตหลุด ระบบลองใหม่ให้เองทุก 4 วินาที
- **รูปสลิปและหลักฐานการแพ็ก** อัปโหลดขึ้นคลาวด์อัตโนมัติ ไม่กินพื้นที่ฐานข้อมูล
- **เลขออเดอร์** ฐานข้อมูลเป็นคนออกให้ ต่อให้ลูกค้าสองคนกดสั่งพร้อมกันก็ไม่ซ้ำ

## สิ่งที่ยังไม่ได้ทำ (พูดตรง ๆ)

1. **หน้าร้านยังต้องล็อกอินก่อนสั่งซื้อ** — คนที่ยังไม่ล็อกอินดูสินค้าได้ แต่จะสั่งซื้อต้องมีบัญชีก่อน
   ตั้งใจให้เป็นแบบนี้ เพราะออเดอร์ต้องผูกกับเจ้าของเพื่อกันคนอื่นมาดู

2. **จำนวนเงินในสลิปยังต้องให้คนตรวจ** — ระบบตรวจรูปแบบสลิปให้ แต่ยังยืนยันกับธนาคารไม่ได้
   ถ้าอยากได้แบบยืนยันจริง ต้องต่อ API ตรวจสลิปของธนาคาร (มีค่าบริการรายครั้ง)

3. **AmiAmi ยังไม่ได้ยืนยันของจริง** — ดูตารางในขั้นที่ 9

4. **Google Sheets ยังเป็นการจำลอง** — ถ้าจะให้ซิงก์จริงต้องต่อ API เพิ่ม

5. **สำรองข้อมูล** — แผนฟรีของ Supabase สำรองให้ 7 วัน ถ้าใช้จริงจังแนะนำอัปเกรด Pro หรือกด Export เก็บเองเป็นระยะ
